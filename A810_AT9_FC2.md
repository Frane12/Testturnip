# A810 AT9 FC2 Measured Rescue — experimental draft

Derived from the tested, compiled AT8 + CP1 branch at 102a8b30f81bb4fbd352335f7e9aa72c30e3223b.

## Why
From supplied fc2gputrace.csv: 3,550 sampled decisions, 2,747 GPU timestamps, 723 RP hashes. The primary FC2 class at 522240 px, 10 tiles, SYSMEM=0 and GMEM=16 bytes/pixel has notably inconsistent GMEM vs SYSMEM performance across render passes and scenes. For high drawcount (>=192), 13 of 18 hashes with >=2 measured GPU samples of each mode had lower SYSMEM median. This is not proof of global FPS improvement and GPU durations may change with the scene. AT7 labeled only 6 decisions; AT8 labeled 0.

## Single experiment: FC2-class A810 pass policy
- Keep Mesa, AT4, AT6, AT63, AT7, AT8 and CP1 unchanged.
- Early prior: if same geometry, >=192 draws and fewer than 3 paired samples, use **64% SYSMEM** instead of an unconditional preference. AT4 forced probes and stronger existing policy still take priority. Stops after 3 paired samples.
- Measured rescue: same geometry, >=48 draws, >=3 paired samples, sufficient MAD-discounted GPU timestamp saving (>=300us for 3 pairs, >=200us for >=4), confidence score >=10/6 respectively, noise <=72/96, volatility <=5, fresh contexts. This can correct a previous non-probing AT4 choice.
- Final GMEM safety and depth/frontier correctness are unchanged; no new queries, command submission instrumentation, expensive CPU allocations, or waits.
- Default AT9=ON; `TU_FRANE_AT9=0` restores AT8 selection in the SAME BINARY. Existing flags are default ON. GPU/CPU file trace default OFF.

## Optional GPU CSV log
```ini
TU_AUTOTUNE_ALGO=profiled
TU_FRANE_AT9=1
TU_FRANE_A810_RFC1_TRACE_PATH=/sdcard/Download/fc2_at9_gpu.csv
```

Expected decision source labels: `AT9_FC2_GPU_RESCUE` or `AT9_FC2_PRIOR` when the new path is used, and GPU_TIMESTAMP TIMING rows with measured nanoseconds. If the path is not writable in your emulator, choose an absolute app-private path.

For unbiased benchmark comparisons leave CSV logging **disabled** and perform at least 3 warm runs with AT9=1 and AT9=0, using ABBA order and fixed resolution, FEX, DXVK, CPU affinity, and Max Frame Latency ON. Ignore the cold run. It is experimental, and improved FPS cannot be claimed until hardware tests.

This is not a published release. The draft release itself is private to users with permission, but source branches in a public repository are publicly visible.
